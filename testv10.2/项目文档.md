飞书写表层(bitable_writer)链路拆解
① 建表/换表:auto_named_table(bitable_writer.py:819)
v10.2 六个模块(情绪/轮动×2/个股榜/竞价/尾盘)全都走这条,v10.2 专属版(相对旧 auto_panorama_table,表名和字段都参数化):


auto_named_table(app_token, 表名, fields)
│
├─ 缓存查: (app_token, 表名) → table_id 命中直接返回 (模块级 _TABLE_CACHE)
│           正结果缓存: 表名含日期, 跨日自然失效 (新日期 key 不命中)
│           负结果缓存: 建表失败 5min TTL, 避免短时重试风暴
│
├─ 锁 _TABLE_CACHE_LOCK 包住 check-then-act (防多线程同时建重复表)
│
├─ GET /tables → 遍历找同名校
│     ├─ 命中: 缓存 + 返回
│     └─ 未命中: POST 建表
│
└─ 锁外补字段 (_add_named_fields, 避免长持锁):
      ├─ 主键字段(表自带第一个字段) PUT 改名 → 时间 type=5 (复用, 不新建)
      └─ 其余字段 _create_field 逐条 POST
设计亮点:缓存写表_TABLE_CACHE 先于补字段——表 id 先给调用方用,字段稍后补。若字段没补完,append_records 的 _list_fields 校验会跳过本轮写入,下一轮再补。首次建表那一行会有"丢"的风险(表建了字段没齐,写被跳过),但只影响首行,盘中后续行都稳。

② 字段类型映射(_create_field,bitable_writer.py:366)
type	含义	property	用在哪
1	文本	—	板块名/候选/结论/热门Top
2	数字	—	分数/家数/成交/封单
3	单选	options(带颜色)	档位(偏暖)、轮动类型(行业/概念)
5	日期时间	date_formatter	时间主键
7	复选框	—	是否涨停(旧表)
单选字段必须预建 options,写记录时值必须是 options 之一。这就是各模块 _build_record 里 if v is None or v == '': continue 的原因——空值跳过,防止单选字段写不存在的 option 报错。

③ 写记录:append_records(bitable_writer.py:197)

记录 → _list_fields 取现有字段集 known
  ├─ 剔除不在 known 的键
  ├─ 逐键 _validate_record_field 类型校验:
  │    文本→str / 数字→int,float / 单选→str / 日期→int / 复选框→bool
  │    不匹配 → 剔除该键 (日志警告, 不整条丢)
  └─ POST /records/batch_create
容错哲学:单字段类型不匹配→剔除该字段,不整条丢。P0-3 修复的产物——一个无关字段类型错了不会让核心数据(综合分/涨停数)跟着丢。

④ 单位换算链路(_build_record,sentiment_monitor.py:367)
写表前,_build_record 做两件事:派生键单位换算 + SENTIMENT_FIELDS 顺序逐键取值:

派生键	换算	原始值→表值
_fcamo_yi 封单均额	avg_fcamo / 1e4	0.58亿 万元→亿
_main_yi 主力流入	main_net / 1e4	+454亿 万元→亿
_amt_yi 今日成交	amount_today / 1e8	2.68万亿 万元→万亿
_amt_y_prev 昨日成交	amt_y / 1e8	2.68万亿
_hs300/_cyb/_kc50/_sz	idx_chgs 拆分	各指数涨幅%
其余(分数/家数/封板率/亏钱比)直传 result,零换算。

两条单位主线对上了(和前面字段单位铁证一致):

avg_fcamo(封单均额,万元)/1e4 → 亿
amount_today(880001 Amount,万元)/1e8 → 万亿
main_net(880001 Zjl_HB,万元)/1e4 → 亿
⑤ 与旧全景表的对比(为什么有 auto_named_table)
auto_panorama_table(情绪全景/板块梯队/打板梯队/板块联动)字段硬编码在 PANORAMA_FIELDS/HEATMAP_FIELDS...。auto_named_table 把表名 + 字段全参数化——*6 张 v10.2 表不需要在 bitable_writer 里各写一份字段定义,每模块自己的 _FIELDS 就够。新增一个榜单 = 新建一个模块 + 自己的 *_FIELDS,零改 writer。

一句话总结写表层:建表(缓存+锁+主键改名)→ 逐字段建(类型/options)→ 写记录(known 过滤+类型校验,坏字段剔除不丢整条)→ 单位换算在模块层 _build_record 完成,writer 只负责结构化落盘。
