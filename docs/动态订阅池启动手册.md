# 动态订阅池启动手册

> 手工启动顺序 + 验收检查点. 适用于盘中拉起"主调度 + 订阅池 + 扫描器"三件套.
> 配套监工程序: `scripts/monitor_services.py`
> 最后更新: 2026-07-24 (commit e339847 + 监工/文档)

---

## 一、架构速览 (3 进程, 零串联)

```
┌─────────────────────────┐   ┌──────────────────────────┐   ┌─────────────────────────┐
│  runner/intraday_loop   │   │ runner/sub_pool_         │   │ collect/scanner_runner  │
│  (主调度, 现役不动)      │   │     supervisor           │   │ (扫描器, 产候选)         │
│                         │   │ (订阅池, 触发即弃)        │   │                         │
│  c1→c2→c3→异动→策略→推送 │   │  读候选→订阅→卸载→冷却   │   │  读 qd_pricevol→评分    │
│         │               │   │         ▲                │   │  →写 SQLite 候选池      │
│         ▼ 写 QuestDB    │   │         │ 读 SQLite      │   │         │               │
│   qd_pricevol (c1)      │   │         │                │   │         └───────────────┼──┐
│   qd_stock_snapshot(c2) │   │         └────────────────┼───┼─────────────────────────┘  │ SQLite
│   qd_stock_intraday(c3) │   │                          │   │                            │ (WAL共享)
└─────────────────────────┘   └──────────────────────────┘   └────────────────────────────┘
          │                              │                              │
          └──────────────┬───────────────┴──────────────────────────────┘
                         ▼
                    tqcenter COM (≤100 订阅名额)
```

**关键属性**:
- 3 进程**任意启停**, 互不依赖. 一个挂了另外两个照跑.
- `config/strategies.yaml` 的 `subscribe_pool.enabled` 是**总开关**:
  - `false` (默认): 订阅池/扫描器空转, 不接管, 0 侵入
  - `true`: 订阅池/扫描器真盘工作
- 所有新代码**零侵入** `runner/intraday_loop.py` 和 `compute/subscribe.py`.

## 二、启动前检查

### 2.1 QuestDB 必须先起

```bash
# Windows (用 cmd.exe, 不要用 Git Bash — 会 segfault)
cd K:\QuestDB\bin
questdb.exe start
```

验证端口 8812 通:
```bash
python -c "from lib.qdb import connect, query_one; c=connect(); print(query_one(c,'SELECT 1 AS ok')); c.close()"
# 应输出 {'ok': 1}
```

> QuestDB 自动守护: 根目录 `monitor_questdb.ps1` (PowerShell, 30s 轮询自动拉起)

### 2.2 yaml 开关确认

```bash
python -c "import yaml; c=yaml.safe_load(open('config/strategies.yaml',encoding='utf-8')); sp=c['subscribe_pool']; print('enabled=',sp['enabled'],'cap=',sp['cap'])"
```

- **第一次跑 / 验收**: 保持 `enabled: false` (空转, 不消耗 tqcenter 名额)
- **真盘**: 改 `enabled: true`

### 2.3 心跳目录就绪

```bash
ls logs/heartbeats/
# 应能看到 (跑过一轮后): intraday_loop.ts / sub_pool_supervisor.ts / scanner_runner.ts
```

## 三、启动顺序 (盘中)

### 推荐顺序: QuestDB → 主调度 → 扫描器 → 订阅池

理由: 订阅池依赖候选池有货, 候选池靠扫描器产, 扫描器靠主调度写 `qd_pricevol`. 顺序反了也能跑 (各进程解耦), 但头几分钟订阅池会空转.

#### Step 1: 主调度 (终端 1, 阻塞)

```bash
python runner/intraday_loop.py
```

- 9:15 自动进入交易时段逻辑, 写 `qd_pricevol` / `qd_stock_snapshot` / `qd_stock_intraday`
- 心跳: `logs/heartbeats/intraday_loop.ts`

#### Step 2: 扫描器 (终端 2, 阻塞)

```bash
python collect/scanner_runner.py --daemon
```

- `enabled=true` 时: 每 60s 读 `qd_pricevol`, 筛 ZAF ∈ [5,9], 评分写 SQLite 候选池
- `enabled=false` 时: 空转心跳 (验证架构用)
- 心跳: `logs/heartbeats/scanner_runner.ts` + `.json`

单轮验证 (不常驻):
```bash
python collect/scanner_runner.py --once --dry-run
```

#### Step 3: 订阅池守护 (终端 3, 阻塞)

```bash
python runner/sub_pool_supervisor.py
```

- `enabled=true` 时: 读候选 → `subscribe_hq` → on_data 触发即弃 → 冷却
- `enabled=false` 时: `start()` 直接 return (空转)
- 心跳: `logs/heartbeats/sub_pool_supervisor.ts` + `.json`

单轮验证 (canary 注入 1 只):
```bash
python runner/sub_pool_supervisor.py --once --dry-run --seed-candidate "002747.SZ,埃斯顿,82.5"
```

```bash

# 退出码: 0=全健康, 1=有异常, 2=配置错误
```

```bash
python scripts/monitor_services.py --with-legacy
```

### 监工判定规则

| 服务 | 健康 = | 异常 = | 未知 = |
|---|---|---|---|
| QuestDB | `SELECT 1` 通 | 连接失败/超时 | — |
| Python 进程 | 心跳 ≤ 60s (交易) / 120s (非交易) | 心跳过期 | 心跳文件不存在 (从未启动) |

> **未知 (未启动) 不算异常** — 退出码仍为 0. 只有"明确过期"或"QuestDB 挂"才报异常.

## 六、关停顺序

**任意顺序都安全** (进程解耦). 推荐逆序:

1. `Ctrl+C` 订阅池守护 (终端 3) — 自动 `unsubscribe_hq` 全部, 释放 tqcenter 名额
2. `Ctrl+C` 扫描器 (终端 2)
3. `Ctrl+C` 主调度 (终端 1) — 15:00 收盘会自动退出

> 订阅池守护的 `SIGINT/SIGBREAK/SIGTERM` 处理器会**先 unsubscribe 再退出**, 防名额跨日泄漏.

## 七、故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 监工报 `QuestDB 连接失败` | QuestDB 未启动 | `monitor_questdb.ps1` 自动拉起, 或手动 `questdb.exe start` |
| 监工报 `sub_pool_supervisor 心跳过期` | 进程挂了 / `enabled=false` 空转但没起 | 看心跳 `.json` 的 `enabled` 字段; 重启进程 |
| 订阅池一直空 (无候选) | 扫描器没跑 / 主调度没写 `qd_pricevol` / 全市场无 ZAF∈[5,9] | 先确认扫描器在跑; 非热点日候选池空是正常的 |
| `tqcenter` 报名额满 | 跨日名额泄漏 / 旧 subscribe.py 也在抢 | 只起一个订阅源; 订阅池守护启动时会先 `unsubscribe_hq([])` 清场 |
| 扫描器 `status=timeout` | 单轮 > 1.5s 熔断 (DB 慢) | 看 `scanner_runner.json` 的 `metrics.last_round_ms`; 检查 QuestDB 负载 |

## 八、配置速查 (`config/strategies.yaml` → `subscribe_pool`)

```yaml
subscribe_pool:
  enabled: false          # 总开关. false=空转, true=真盘
  cap: 95                 # 订阅容量 (≤100, 留 5 冗余)
  enter_zaf_low: 5.0      # 入池涨幅下界 %
  enter_zaf_high: 9.0     # 入池涨幅上界 %
  cooldown_sec: 300       # 触发卸载后冷却
  debounce_sec: 10        # L1 抖动闸 (含 critical)
  break_drop_pct: 3.0     # 破位回撤阈
  div_vol_ratio: 2.0      # 量价背离量比下限
  dry_run: false          # true=只打分不订阅
  score_weights:          # 评分权重 (Stage-1 只用 near_limit + vol_surge)
    near_limit: 0.35
    vol_surge: 0.25
    zjl: 0.25             # 订阅后精算, Stage-1=0
    gene: 0.15            # daily 缓存, Stage-1=0
```

> 改 yaml 后需重启对应进程 (不热加载).
